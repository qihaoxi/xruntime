# xruntime 修复回归审计(吸收 PEL pel-fix-regression-audit)

> 起因(实锤教训):PEL auto_stop P1 用"锁内快照 + 锁外检查"换掉写者饥饿,
> 却引入 heap-use-after-free——快照持通道指针,运行期单通道停止撞上锁外检查。
> 隔离/单面全绿都过了,缺陷存在 2 天才在满载矩阵暴露。

## 1. 何时触发

- 修复/重构涉及:锁的获取范围、等待方式、对象快照借用、生命周期(谁 free、
  何时可 free);
- 调度时机类改动:同线程直投(V1)/LIFO slot(V7)/回调内同步完成;
- 数据结构替换:V3 无锁队列、V4 waker 句柄、V6 单字 permit;
- 用户问"是不是之前的修复也有类似问题"/"为修 A 引入 B"/满载才现的翻案。

## 2. 核查清单(核心 = 换出的并发窗口)

1. **被换掉的风险是什么**?旧缺陷的触发条件、原本受哪个互斥/等待保护;
2. **新方案触达的对象,谁会提前 free/复用它**?逐条列出释放/复用路径与时机
   (task DONE 摘除?worker destroy?parker reset 复用?栈帧返回?)——**不要只
   覆盖"worker 停止期"**,PEL 的 UAF 就是只论证了停止期、漏掉运行期;
3. **是否用"生命周期假设"替代了互斥**?必须 (a) 证明覆盖所有并发路径,或
   (b) 给守卫/引用计数/重查兜底;否则退回互斥;
4. **假设能守卫化吗**?能落 assert/grep 守卫就落(constraints §0/§5);
5. **验证是否够**(判定"修复完成"的最低门槛,2026-10-02 分级):
   a. **默认**:`debug` 构建 + 相关 ctest;并发/生命周期改动建议按需
      `tsan`+`asan`(五面全量改为按需/里程碑,不再每变体强制);
   b. **定向压测**:B1/B2 + `test_worker` 高频 unpark/drain(满载窗口);
   c. **确定性回归优先**:能把缺陷做成"入口即触发/不依赖竞速"的用例就必须做
      (修前必红、修后恒绿);统计面只作补充;
   d. **隔离/单面全绿 ≠ 无缺陷**——只能降触发概率,不能反证。

## 3. 追残余:搜"同类形态"而非"同类名字"

修一个纪律违反后,必须按**形态**全仓复查同类旁路(结合统一收口原则):

1. 列出"绕开收口函数直接触达被收口语义"的所有调用点(如绕过 `worker_wake`
   自己 write eventfd、绕过 `task_deliver` 自己 push 队列、绕过 parker 自己
   写 state);
2. 逐点核对收口前后的增支/订阅是否配对;
3. 兄弟路径(parker/worker/bench 各变体)逐个过,别只修眼前那个。

## 4. 数据结构替换型修复的两类盲区(PEL doc146 §0.5 / doc148 D4 实锤)

1. **重排/落位判定用操作前状态**:改有序结构(堆/环/有序链)后自问——所有
   "是否需要 X"的判定,读的是操作前还是操作后的状态?(PEL D4 v3 首版因
   "sift 前下标"漏 rearm,混布超时迟至旧顶才 fire);
2. **同质输入套件对混布/交错形态全盲**:修完自问——套件里有没有"两种量级/
   交错到达"的 case?没有就补(确定性形态优先);
3. **"O(n) 且 n 小"必须按 常数×真实 n 核**:嵌入跨页对象的链表每步是 cache
   miss 常数(实测 50×),选型先问"比较键在不在连续内存、热路径碰几个跨页
   对象"。

## 5. 调度时机型改动的契约审计漏维度(PEL doc152 D8 实锤,本仓红线)

把"异步生效"改成"同步立即生效"(唤醒点直跑/inline/回调内同步完成)时,
除常规重入/嵌套/公平论证外,**必须审计唤醒发起方的栈帧寿命**:

- 完成路径普遍依赖"unpark/notify 仅登记、消费者后跑"的隐含契约——发起函数
  在 unpark **之后**往往还有动作(deliver 返回后 worker 循环继续、timer
  循环、统计更新);同步直跑等于把整条调用栈让渡给消费者,消费者 free 掉
  op/容器后发起方返回即踩已失效帧(PEL D8 SIGSEGV);
- 这是"开门后不得再触碰消费者可能已复用的对象"的**调用栈维度**;
- 修前自问:**unpark/notify 的每个调用点,其后是否还有语句?** 有(几乎必有)
  则同步直跑需要"触发点在完成栈帧收尾后的统一边界"——本仓即 `worker_run_task`
  返回后的 step 边界;若边界已存在,同步化没有新增空间;
- 双重校验:性能假设用实测否决权(PEL D8 的"省 eventfd 往返"被
  `uv_async_send` 同线程免 write、0.16 write/req 实测否决)。

## 6. 输出纪律

- 修复未达 §2.5 门槛前不得标"已修";按"已定位/已修部分/残留窗口"如实登记;
- **证据链先于修法**:先取证(现场/读码/sanitizer 首错),候选修法先测后定、
  被否即留档(PEL doc101);
- **绕过式修复禁令**(PEL doc155 §7.7):不许把"集成/机制本身"当问题源整体
  拆除换替代物再打补丁;关键架构决定必须取证留档进 docs;
- 假设无法 100% 捕获要登记证据缺口,不许跳过;
- 修法须满足"规则数净减或持平"(constraints §4.6);只增不减先问是否有统一
  收敛点替代。

## 7. 工具

- 文本检索一律 `rg`(符号唯一时 `rg -w <sym>` 近似语义引用);
- 语义确认用 clangd/clang-tidy + 各 `build-*/compile_commands.json`:
  `clangd --check=<file> --compile-commands-dir=<build>`;
- 挂死现场:`gstack <pid>`(或 gdb `thread apply all bt`),间隔 5–10s 双采样;
- 常配 skill:`xr-sanitizer`(五面)、`xr-bench-ab`(同窗 A/B 定靶)。
